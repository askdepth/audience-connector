# @askdepth/reference-connector

A **genuine, deployable** Askdepth Audience connector — not a mock. It is built
on the public `@askdepth/audience-connector` package (real `createConnector`,
real `postgresAdapter`, real HMAC signature verification, the real Express
shim) over one seeded synthetic user base of 5,000 rows. It is never published
to npm.

It serves three roles:

- **CI fixture** — the platform's integration tests and the conformance gate
  run against it.
- **Sales demo** — a live connector to point the conformance CLI at, with no
  platform UI in the loop.
- **Reference implementation** — a client engineer reads `src/postgres-variant.ts`
  to see what a correct, idiomatic connector looks like.

## The Postgres variant

`src/postgres-variant.ts` mounts a connector over a real Postgres table
(`reference_users`) loaded from the checked-in seed (`seed/fixtures.sql`,
regenerated by `pnpm --filter @askdepth/reference-connector seed:generate`).

Canonical mapping and attribute config (see `seed/generate.ts`):

| canonical field | store column   |
| --------------- | -------------- |
| `externalId`    | `external_id`  |
| `email`         | `email`        |
| `signupAt`      | `signup_at`    |
| `segment`       | `segment`      |
| `isActive`      | `is_active`    |

| attribute    | filterable | returnable |
| ------------ | ---------- | ---------- |
| `plan`       | yes        | yes        |
| `country`    | yes        | **no** (filter-only) |
| `deviceType` | yes        | yes        |

`internal_notes` and `crm_account_id` exist in every row but are **not** mapped.
They are introspected by `GET /schema` (that is allowed — §S6.16) but must never
appear in a `/candidates/search` row or a `/candidates/count` body.

### Environment

| var                | required | meaning                                                                 |
| ------------------ | -------- | ---------------------------------------------------------------------- |
| `REFERENCE_SECRET` | yes      | HMAC signing secret. No insecure default — the process refuses to start without it. |
| `DATABASE_URL`     | yes\*    | Postgres connection string. `TEST_DATABASE_URL` is accepted as a fallback. |
| `PORT`             | no       | Listen port (default `8787`).                                          |

The connector route prefix is `/askdepth/v1`, so the base URL is
`http://<host>:<port>/askdepth/v1`.

## Running it

### One command (Docker)

```sh
cd packages/reference-connector
docker compose up
```

Brings up `postgres:16` (auto-seeded from `seed/fixtures.sql`) and the
connector on `:8787`, signing with the throwaway secret
`demo-reference-secret`.

### Local (against your own Postgres)

```sh
pnpm --recursive run build            # the variant consumes the *built* package

REFERENCE_SECRET=dev-secret \
DATABASE_URL=postgres://postgres:postgres@127.0.0.1:55432/reference_test \
  pnpm --filter @askdepth/reference-connector demo:postgres
```

`demo:postgres` prints the URL + secret and stays up until Ctrl-C.
`start:postgres` is the same boot without the demo banner (what CI uses).

To load the seed into a running Postgres by hand:

```sh
psql "$DATABASE_URL" -f packages/reference-connector/seed/fixtures.sql
```

## Conformance

Run the built public CLI against the variant. This is the exact invocation the
`reference-postgres` CI job asserts exits `0`:

```sh
node packages/connector/dist/bin/conformance.js conformance \
  --url http://localhost:8787/askdepth/v1 --secret dev-secret \
  --unmapped-column internal_notes --unmapped-column crm_account_id \
  --filter-only-attribute country
```

- `--unmapped-column` — feeds case **N3** the out-of-band list of sensitive
  store columns that must not leak into candidate data.
- `--filter-only-attribute country` — tells case **P6** which advertised
  attribute is filter-only, so it can assert `country` never appears in a row.

All 15 cases (7 positive + 8 negative) must pass.

## Tests

```sh
pnpm --filter @askdepth/reference-connector test
```

`__tests__/postgres-variant.test.ts` is gated on `TEST_DATABASE_URL` /
`DATABASE_URL`: it skips cleanly with no database, and is mandatory in CI. With
a database present it boots the variant in-process, runs the full 15-case suite
through the built CLI, and re-asserts the `GET /schema` introspection shape.
